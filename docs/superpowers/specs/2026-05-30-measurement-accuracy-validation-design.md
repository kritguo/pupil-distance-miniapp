# 测量精度离线验证 — 设计文档

- 日期:2026-05-30
- 状态:已通过 brainstorming,待写实现计划
- 范围标签:`measurement-accuracy-validation`

## 1. 背景与问题

「测瞳距」小程序当前用 **虹膜水平直径(HVID≈11.7mm)当比例尺** 计算瞳距(`cloud-service/main.py` v3.0)。
链路:拍照 → MediaPipe 测虹膜中心+直径 → 总 PD = 双虹膜像素距 × (11.7 / 虹膜像素直径) → 鼻梁投影分左右单眼 → 远/近用换算 → 姿态质量校验 → 前端拍 3 张取中位数。

这个方法绕开了「卡片与眼睛不共面」的深度误差,设计合理。但精度上有两个未解决的根本问题:

1. **「人人虹膜 11.7mm」是固定假设。** 真人虹膜直径有个体差异(约 ±0.5mm,即 ±4%)。某人实际 12.2mm 却按 11.7 计算,其每次 PD 都会系统性偏约 2.5mm,且**拍多张取中位数也消不掉**(属个人固定偏差)。这是当前精度天花板。
2. **从未用真实验光 PD 标定。** `PD_CALIBRATION` 系数默认 1.0,从没校准过。**我们根本不知道方法整体偏高还是偏低、偏多少。**

> 核心结论:当前最大的问题不是「算法不够好」,而是「不知道它有多准」。在拿到真值对照前改算法等于蒙眼调参。**先测量,再优化。**

本设计只解决「测量误差」这一步,**不改算法、不改小程序**。改算法是下一轮工作,且必须用本工具当裁判。

## 2. 目标与非目标

### 目标
- 建立一套**离线批量精度验证**能力:输入「带真实 PD 真值的人脸照片」,输出量化误差报告。
- 报告必须能直接回答:
  - 方法整体偏差多少?分散度多大?±1mm / ±2mm 命中率多少?
  - 最优全局标定系数 `PD_CALIBRATION` 应设为几?标定前后误差对比?
  - 个体虹膜差异有多大?是否值得做「个人虹膜标定」(后续方案②)?
  - 误差与哪些因素(偏头/质量分/眼睛开合/分辨率)相关?校验阈值是否合理?
  - 有卡片时,卡片 PD 是否比虹膜 PD 更接近真值?(验证后续方案②价值)
- 可反复重跑,作为后续任何算法改动的**精度回归测试**。

### 非目标(YAGNI)
- ❌ 不修改测量算法本身(`main.py` 的计算逻辑这轮不动)。
- ❌ 不修改小程序前端。
- ❌ 不做小程序内在线真值采集(等本工具跑出信号、确需持续大规模采集时再议)。

## 3. 真值来源

已确认:用户能提供**人脸照片 + 对应的真实验光 PD**。这是最理想的真值形式,因此采用纯离线批量方案,无需任何在线采集。

## 4. 方案设计

### 4.1 数据集格式(用户准备,一次性)

```
cloud-service/validation/
├── dataset/
│   ├── images/            # 正脸照片:001.jpg, 002.jpg ...
│   └── labels.csv         # 真值表
```

`labels.csv` 字段:

```
filename, subject_id, true_pd_total, true_pd_left, true_pd_right, notes
001.jpg,  zhang,      63.0,          31.5,         31.5,         验光单
```

- `true_pd_left` / `true_pd_right` 可留空(只验总 PD 也行)。
- `subject_id`:同一个人多张照片归为一组,用于量化个体虹膜差异。
- 缺图、缺真值、检测失败的行需被报告显式列出,不能静默跳过。

### 4.2 跑批脚本 `cloud-service/validation/run_validation.py`

- **直接 import `main.py` 的算法函数**(`detect_iris` / `calculate_pd_iris` / `detect_card_opencv` / `calculate_pd_card` / `validate` / `assess_quality` 等),不走网络。
  - 好处:确定性强;可在脚本内**扫不同 CALIBRATION 系数**而无需重新部署服务。
  - 基线以 `PD_CALIBRATION=1.0` 跑,标定系数在分析阶段解析式求解(测量值对系数线性)。
- 运行环境:复用 `cloud-service` 的 Python 环境与 `requirements.txt`(mediapipe / opencv / numpy)。若无本地 venv,提供一键建环境说明,或在 Docker 镜像内运行。
- 逐张采集字段:测得 总/左/右 PD、虹膜直径(avg/left/right px)、瞳孔像素距、质量分、各项 validation 标志、卡片对照 PD,与真值拼接。

### 4.3 误差报告(脚本输出)

1. **逐样本表**:filename、subject、真值、测量值、误差(mm)、绝对误差、质量分、关键校验标志。
2. **总体指标**:平均误差(系统偏差)、标准差、MAE、P50/P90/最大绝对误差、**±1mm / ±2mm 命中率**。
3. **最优全局标定**:测量值对系数线性,解析求出最优 `PD_CALIBRATION`。**主目标 = 最小化总 PD 的 MAE**(更稳健、对离群点不敏感);同时附带列出「令平均误差归零」的无偏系数作参考。给出「标定前 vs 标定后」误差对比,直接输出「建议设为 X」。
4. **个体虹膜分析**:从真值反推每个人的有效虹膜直径 = `true_pd_total × diam_avg_px / pupil_px`,统计人群分散度,量化 #1 误差,判断是否值得做个人标定。
5. **残差相关性**:误差 vs 偏头(虹膜不对称)/质量分/眼睛开合/图像分辨率,辅助校验阈值调参。
6. **卡片对照**:在检出卡片的样本上,比较「卡片 PD」与「虹膜 PD」谁更接近真值。

输出形式:控制台摘要 + `cloud-service/validation/reports/` 下一份逐样本 CSV 和一份 markdown 报告,commit 存档。

## 5. 模块边界

| 单元 | 职责 | 依赖 |
|---|---|---|
| `labels.csv` + `images/` | 真值数据集(用户提供) | 无 |
| 数据加载器 | 读 labels.csv、配对图片、校验完整性、列出缺失行 | 标准库 csv |
| 测量适配器 | 调 `main.py` 算法函数,把单图跑成结构化结果 | `main.py`、mediapipe、opencv |
| 误差分析器 | 拼接真值与测量值,算各项指标与最优标定 | numpy |
| 报告器 | 输出控制台 / CSV / markdown | 标准库 |

每个单元可独立测试:加载器对「缺图/缺真值」给明确报错;分析器对构造的已知输入给已知指标;适配器对一张样图给稳定输出。

## 6. 错误处理

- 缺图片 / 缺真值字段 / 检测不到人脸 / 虹膜不可信:**逐条记入报告的「无效样本」区**,不污染统计,不静默丢弃。
- 数据集为空或全部失败:明确报错并提示检查路径与格式。
- 真值字段非数字:报错并指出行号。

## 7. 验收标准

- 给一个含 N 张已标注照片的数据集,脚本能跑完并产出包含上述 6 块内容的报告。
- 报告给出明确的「建议 `PD_CALIBRATION` 值」及标定前后误差对比。
- 无效样本被显式列出,有效样本统计不被污染。
- 脚本可重复运行,结果稳定(同输入同输出)。

## 8. 后续(不在本轮范围)

拿到本轮报告后,再据数据决定下一轮优化优先级:
- 全局标定:按报告设 `PD_CALIBRATION`。
- 方案②:卡片个人虹膜标定(若报告显示个体差异大且卡片更准)。
- 方案③:偏头几何校正、虹膜亚像素/高清裁剪、3→5 张中位数。
- 每轮改完都用本工具重跑回归。
