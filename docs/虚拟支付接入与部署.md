# 虚拟支付接入与部署清单

本项目支付走微信小程序 **虚拟支付**(`wx.requestVirtualPayment`,道具直购模式),
而非传统微信支付(云支付 unifiedOrder)。原因:iOS 卖虚拟内容强制走虚拟支付。

权益(单次次数 / 年度会员)以服务端 `users` 集合为准,本地只做缓存。

## 一、套餐 ↔ 道具(后台已建,发布现网)

| plan | 道具ID | 价格 | 发放权益 |
|---|---|---|---|
| `single` | `single_pack_3` | ¥9.9 | 剩余次数 +3(可测 3 次,每次自动拍 3 张取中位数) |
| `annual` | `annual_member` | ¥19.9 | 年度会员,到期时间 +365 天 |

> 道具ID 写死在 `cloudfunctions/vpaySign`(下单)和 `cloudfunctions/vpayNotify`(发货发权益)里。
> 改道具ID 必须同步改这两个云函数。已去掉旧的 ¥10「补差价升级」(未建对应道具)。

## 二、云函数(逐个右键「上传并部署:云端安装依赖」)

- `vpaySign` — `wx.login` 的 code 换 session_key,组 signData 并签 paySig/signature,落 pending 订单。
- `vpayNotify` — 收发货推送 `xpay_goods_deliver_notify`,幂等发放权益到 `users`,返回 `ErrCode:0`。
- `getEntitlement` — 查询当前用户权益(沿用)。
- `consumeMeasure` — 单次套餐看结果时按结果时间戳扣 1 次,幂等(沿用)。

依赖均为 `wx-server-sdk`,首次部署勾「云端安装依赖」。部署环境用 `cloud1-0gahgwwra45a0df3`
(即 `config.cloud.envId`,`app.js` cloud.init 用的环境;注意不是测量容器那个 `prod-d2gxdl8ua...`)。

## 三、云函数环境变量(必做,否则下单失败)

在云开发控制台 → 云函数 → `vpaySign` → 配置 → 环境变量:

```
VPAY_APP_KEY = 虚拟支付 appKey(公众平台→虚拟支付→基本配置,沙箱/现网各一个,联调先用沙箱)
WX_APP_SECRET = 小程序 AppSecret(公众平台→开发管理→开发设置)
VPAY_OFFER_ID = 虚拟支付二级商户号 offerId
VPAY_ENV = 1   # 1=沙箱联调 / 0=现网。iOS 强制 0
```

> appKey / AppSecret 是密钥,只配在云函数环境变量里,**不要提交进 git、不要写进前端**。

## 四、数据库集合

云开发 → 数据库,确保有 `orders` 和 `users` 两个集合,权限设为
「仅创建者可读写」或「所有用户不可读写」(只让云函数管理员权限写,防前端伪造权益)。

- `orders`:`outTradeNo, openid, plan, productId, amount, status(pending/paid), channel:'virtual', createTime, payTime`
- `users`:`_id=openid, remainCount, totalSinglePurchased, annualExpireAt, consumedResults[], createTime, updateTime`

## 五、消息推送 → vpayNotify(发货回调)

公众平台 → 虚拟支付 / 开发设置 → 消息推送,把发货事件 `xpay_goods_deliver_notify`
推送到 `vpayNotify` 云函数。支付成功后微信推送该事件,vpayNotify 发权益并回 `ErrCode:0`。

> ⚠️ **待沙箱核对**:推送事件的确切字段名(openid / out_trade_no / product_id)。
> `vpayNotify` 已做多写法兜底,并 `console.log` 原始 event;沙箱跑一笔后看日志按需微调。

## 六、iOS 适配

- iOS 走苹果内购,费率本为 17%(苹果12%+腾讯5%),**2026 年限时减免至 0%**。
- iOS 必需:公众平台「虚拟支付→基本配置」**配置小程序简称**(满足苹果 display name)。
- 代码无差异,`requestVirtualPayment` 平台自动路由。用户需 iOS15+、微信 8.0.68+。

## 七、沙箱自测流程

1. `VPAY_ENV=1`,真机/体验版(模拟器拉不起支付)。
2. 测量出结果 → 付费弹窗 → 选「3 次测量包 ¥9.9」→ 支付。
3. 看 `vpayNotify` 日志确认收到发货推送;`orders` 该单 status→paid;`users` 出现 remainCount=3。
4. 结果页解锁、`我的` 显示「剩余 N 次」。
5. 测年度会员:`users.annualExpireAt` = 一年后;`我的` 显示「年度会员 · 有效期至…」。
6. 清缓存重进,权益仍在(来自服务端 getEntitlement)。
7. 沙箱通过后:改 `VPAY_ENV=0`、`VPAY_APP_KEY` 换现网值,提交现网审核。

## 八、待办 / 风险

- **签名与回调字段沙箱核对**:paySig/signature 公式已按官方文档实现,但 signData 字段细节
  与发货推送字段名需沙箱实测确认(15006 PAY_SIG_INVALID 多为 signData 字符串不一致所致)。
- **卡密兑换**(activate 页)仍是本地模拟,未接服务端(单独事项)。
- **精度实测**:与支付无关,见 `cloud-service/validation/`。
