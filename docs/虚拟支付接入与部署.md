# 虚拟支付接入与部署清单

本项目支付走微信小程序 **虚拟支付**(`wx.requestVirtualPayment`,道具直购模式),
而非传统微信支付(云支付 unifiedOrder)。原因:iOS 卖虚拟内容强制走虚拟支付。

发权益用 **主动查单** 模式(支付成功后云函数查单 + 发货确认 + 发权益),
**不需要配置消息推送/服务器回调**。权益以服务端 `users` 集合为准。

## 一、套餐 ↔ 道具(后台已建,发布现网)

| plan | 道具ID | 价格 | 发放权益 |
|---|---|---|---|
| `single` | `single_pack_3` | ¥9.9 | 剩余次数 +3(可测 3 次,每次自动拍 3 张取中位数) |
| `annual` | `annual_member` | ¥19.9 | 年度会员,到期时间 +365 天 |

> 道具ID 写死在 `vpaySign`(下单)和 `vpayConfirm`(查单发权益)里,改道具ID 要同步改这两个云函数。
> 已去掉旧的 ¥10「补差价升级」(未建对应道具)。

## 二、云函数(逐个右键「上传并部署:云端安装依赖」)

- `vpaySign` — `wx.login` 的 code 换 session_key,组 signData 并签 paySig/signature,落 pending 订单。
- `vpayConfirm` — 支付成功后查单(query_order),已支付则幂等发权益到 `users`,并确认发货(notify_provide_goods,防自动退款)。
- `getEntitlement` — 查询当前用户权益(沿用)。
- `consumeMeasure` — 单次套餐看结果时按结果时间戳扣 1 次,幂等(沿用)。

依赖均为 `wx-server-sdk`,首次部署勾「云端安装依赖」。部署到环境 `cloud1-0gahgwwra45a0df3`
(即 `config.cloud.envId`,app.js cloud.init 用的环境;不是测量容器那个 `prod-d2gxdl8ua...`)。

## 三、云函数环境变量(配在 vpaySign 和 vpayConfirm 两个上)

云开发控制台 → 云函数 → 选函数 → 配置 → 环境变量:

```
VPAY_APP_KEY = 虚拟支付 appKey(公众平台→虚拟支付→基本配置,沙箱/现网各一个,联调先用沙箱)
WX_APP_SECRET = 小程序 AppSecret(公众平台→开发管理→开发设置)
VPAY_OFFER_ID = OfferID(支付应用ID)。注意不是「微信支付商户号」  ← 仅 vpaySign 需要
VPAY_ENV = 1   # 1=沙箱联调 / 0=现网。iOS 强制 0
```

- `vpaySign` 需要全部 4 个;`vpayConfirm` 需要 `VPAY_APP_KEY` / `WX_APP_SECRET` / `VPAY_ENV`(它不用 OFFER_ID)。
- appKey / AppSecret 是密钥,只配在环境变量里,不要提交进 git、不要写进前端。
- 改完环境变量需重新部署对应函数才生效。

## 四、数据库集合

云开发 → 数据库,确保有 `orders` 和 `users` 两个集合,权限设为
「仅创建者可读写」或「所有用户不可读写」(只让云函数管理员权限写,防前端伪造权益)。

- `orders`:`outTradeNo, openid, plan, productId, amount, status(pending/paid), channel:'virtual', createTime, payTime`
- `users`:`_id=openid, remainCount, totalSinglePurchased, annualExpireAt, consumedResults[], createTime, updateTime`

## 五、支付流程(主动查单,无需消息推送)

1. 前端 `wx.login` 拿 code → 调 `vpaySign` 拿 signData/paySig/signature(并落 pending 订单)。
2. `wx.requestVirtualPayment` 拉起支付。
3. 支付成功(弱确认)→ 前端调 `vpayConfirm`(传 outTradeNo)。
4. `vpayConfirm` 查单:已支付则发权益 + 确认发货;前端再同步 `getEntitlement` 刷新本地。

> 因此**不需要配置消息推送/服务器 URL**。那个「消息推送配置」界面可以不管。

## 六、iOS 适配

- iOS 走苹果内购,费率本为 17%(苹果12%+腾讯5%),**2026 年限时减免至 0%**。
- iOS 必需:公众平台「虚拟支付→基本配置」**配置小程序简称**(满足苹果 display name)。
- 代码无差异,`requestVirtualPayment` 平台自动路由。用户需 iOS15+、微信 8.0.68+。

## 七、沙箱自测流程

1. `VPAY_ENV=1`,vpaySign / vpayConfirm 都用沙箱 appKey,真机/体验版(模拟器拉不起支付)。
2. 测量出结果 → 付费弹窗 → 选「3 次测量包 ¥9.9」→ 支付。
3. 看 `vpayConfirm` 日志:query_order 返回、status、发货确认结果。
4. 数据库 `users` 该 openid 出现 `remainCount: 3`;结果页解锁、「我的」显示「剩余 N 次」。
5. 测年度会员:`users.annualExpireAt` = 一年后;「我的」显示「年度会员 · 有效期至…」。
6. 清缓存重进,权益仍在(来自服务端 getEntitlement)。
7. 沙箱通过后:改 `VPAY_ENV=0`、`VPAY_APP_KEY` 换现网值,重新部署,提交现网审核。

## 八、待办 / 风险

- **签名与查单字段沙箱核对**:paySig 公式已按官方实现(`hmac_sha256(appKey, uri+'&'+body)`),
  但 `query_order` 返回里 status 的层级、signData 字段细节需沙箱实测确认
  (15006 PAY_SIG_INVALID 多为待签字符串与实际发送不一致所致)。`vpayConfirm` 已打印原始响应便于联调。
- **卡密兑换**(activate 页)仍是本地模拟,未接服务端(单独事项)。
- **精度实测**:与支付无关,见 `cloud-service/validation/`。
