# 微信支付接入与部署清单

本项目支付走 **微信云开发云支付**（`cloud.cloudPay.unifiedOrder`），不用自建服务器、不用管证书签名。
权益（单次次数 / 年度会员）以服务端 `users` 集合为准，本地只做缓存，清缓存/换手机不会丢失。

## 一、套餐与定价（服务端为准）

定价表写死在云函数 `payOrder` 和 `payCallback` 里（单位：分），前端只传 `plan`，金额一律以服务端为准：

| plan | 金额 | 发放权益 |
|---|---|---|
| `single` | ¥9.9 (990) | 剩余次数 +3 |
| `annual` | ¥19.9 (1990) | 年度会员，到期时间 +365 天 |
| `upgrade` | ¥10 (1000) | 年度会员，到期时间 +365 天（单次升级补差价） |

> 改价格：同时改 `cloudfunctions/payOrder/index.js` 和 `cloudfunctions/payCallback/index.js` 里的 `PRICING`，并改前端展示文案（result.wxml / index.wxml）。

## 二、数据库（云开发 → 数据库，新建两个集合）

1. **orders**（订单）：`outTradeNo, openid, plan, amount, status(pending/paid/failed), transactionId, createTime, payTime`
2. **users**（权益）：文档 `_id = openid`，字段 `openid, remainCount, totalSinglePurchased, annualExpireAt, consumedResults[], createTime, updateTime`

权限建议：两个集合都设为 **「仅创建者可读写」或「所有用户不可读写」**（只让云函数用管理员权限读写），不要开放客户端直接写，否则权益可被前端伪造。

## 三、云函数（4 个，逐个右键「上传并部署：云端安装依赖」）

- `payOrder` — 统一下单 + 写 orders
- `payCallback` — 支付结果回调（发放权益）
- `getEntitlement` — 查询当前用户权益
- `consumeMeasure` — 单次套餐看结果时扣 1 次（按结果时间戳幂等）

依赖都是 `wx-server-sdk`，首次部署勾选「云端安装依赖」。

## 四、关键配置（必须做，否则下单会失败）

### 1. 配置商户号环境变量
`payOrder` 通过 `process.env.SUB_MCH_ID` 读取你的微信支付商户号。
在云开发控制台 → 云函数 → `payOrder` → 配置 → **环境变量** 添加：

```
SUB_MCH_ID = 你的微信支付商户号(mch_id)
```

### 2. 关联微信支付商户号到云开发
- 微信支付商户平台：把小程序 AppID（`wxb70011e77b4c76fc`）与商户号完成 **AppID 账号关联**。
- 云开发控制台 → 设置 → **支付** / 商户号关联，按引导把商户号与当前云环境绑定（开通「云支付」能力）。
  - 这一步是云支付能下单的前提；未关联时 `unifiedOrder` 会返回失败。

### 3. 回调函数
代码里下单时已指定 `functionName: 'payCallback'`、`envId: 当前环境`，**无需在商户平台单独配回调 URL**——云支付会直接回调到这个云函数。确保 `payCallback` 已部署。

## 五、自测流程

1. 微信开发者工具用 **真机调试** 或 **体验版**（云支付需真实环境，模拟器无法拉起支付）。
2. 进入测量 → 出结果 → 弹付费弹窗 → 选「3 次测量包 ¥9.9」→ 确认支付。
3. 支付成功后：
   - `orders` 该订单 `status` 变 `paid`；
   - `users` 该 openid 出现 `remainCount: 3`；
   - 结果页解锁，`我的` 页显示「剩余 N 次」。
4. 测「年度会员 ¥19.9」：`users.annualExpireAt` = 一年后时间戳，`我的` 显示「年度会员 · 有效期至 YYYY-MM-DD」。
5. 验证防白嫖：清小程序缓存后重进，权益仍在（来自服务端 `getEntitlement`）。
